1. ЦЕЛЬ РАБОТЫ

Освоить отправку HTTP-запросов из React-приложения к REST API, обработку
состояний загрузки и ошибок и обновление интерфейса по данным сервера.
Реализовать связь клиентской части проекта управления музыкальными
плейлистами с API на Node.js, Express и PostgreSQL.


2. СХЕМА ВЗАИМОДЕЙСТВИЯ

Пользователь открывает React-клиент в браузере. Компонент App при монтировании
запрашивает список плейлистов у сервера через Axios. Во время запроса
отображается индикатор загрузки. Сервер Express обрабатывает запросы и читает
или изменяет записи в PostgreSQL через Sequelize.

Для создания, изменения и удаления плейлистов пользователь входит в аккаунт.
Клиент отправляет email и пароль на сервер, получает JWT и сохраняет его в
localStorage. Axios interceptor добавляет JWT в заголовок Authorization
каждого API-запроса. Сервер проверяет подпись токена и роль пользователя.
Изменение данных разрешено только роли admin.

При POST, PUT и DELETE клиент сначала оптимистически меняет состояние React,
не дожидаясь ответа сервера. Если запрос завершился ошибкой, клиент
восстанавливает прежнее состояние и показывает сообщение. Для начальных GET
запросов используется AbortController, отменяющий запрос при очистке эффекта.
Во время разработки Vite перенаправляет /api запросы на Express-сервер.

Схема:

Пользователь
    |
    v
React App (useState/useEffect)
    |
    v
Axios API service -- Authorization: Bearer JWT
    |
    v
Vite proxy /api (dev) --> Express REST API
                              |
                         JWT / RBAC middleware
                              |
                              v
                    Sequelize --> PostgreSQL
                              |
                              v
                      JSON-ответ клиенту


3. РЕАЛИЗАЦИЯ И ЛИСТИНГИ

3.1 Файл client/src/api.js

Сервис инкапсулирует HTTP-запросы. Interceptor добавляет сохранённый JWT.
Ниже приведены ключевые фрагменты; полный файл находится в проекте
client/src/api.js.

Создание Axios-клиента и добавление токена:

const TOKEN_KEY = 'stpp-auth-token'

const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL || '/api',
  headers: { 'Content-Type': 'application/json' },
})

api.interceptors.request.use((config) => {
  const token = window.localStorage.getItem(TOKEN_KEY)
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

Получение списка и CRUD-запросы:

export async function getPlaylists({ signal } = {}) {
  const response = await api.get('/playlists', { signal })
  return response.data.data
}

export async function createPlaylist(playlist) {
  const response = await api.post('/playlists', playlist)
  return response.data.data
}

export async function updatePlaylist(id, playlist) {
  const response = await api.put(`/playlists/${id}`, playlist)
  return response.data.data
}

export async function deletePlaylist(id) {
  await api.delete(`/playlists/${id}`)
}

Также сервис содержит функции register(credentials), login(credentials),
getProfile({ signal }) и getApiErrorMessage(error). Удаление получает от
сервера статус 204 No Content, поэтому JSON-тело ответа не читается.

3.2 Файл client/src/App.jsx

Основной компонент хранит список и состояние загрузки, состояние ошибки,
данные входа, профиль пользователя и поля формы. При монтировании useEffect
запрашивает плейлисты; AbortController отменяет запрос при очистке эффекта.

Загрузка и отмена запроса:

useEffect(() => {
  const controller = new AbortController()
  let isActive = true

  getPlaylists({ signal: controller.signal })
    .then((data) => {
      if (isActive) setPlaylists(data)
    })
    .catch((error) => {
      if (isActive && error.name !== 'CanceledError') {
        setLoadError(getApiErrorMessage(error))
      }
    })
    .finally(() => {
      if (isActive) setIsLoading(false)
    })

  return () => {
    isActive = false
    controller.abort()
  }
}, [loadVersion])

Оптимистическое добавление:

setPlaylists((current) => [temporaryPlaylist, ...current])
try {
  const savedPlaylist = await createPlaylist(playlistData)
  setPlaylists((current) =>
    current.map((item) => item.id === temporaryId ? savedPlaylist : item),
  )
} catch (error) {
  setPlaylists((current) =>
    current.filter((item) => item.id !== temporaryId),
  )
  setActionMessage(`Не удалось создать плейлист: ${getApiErrorMessage(error)}`)
}

Редактирование и удаление также сначала меняют состояние интерфейса. При
неудачном PUT прежний объект возвращается в список; при неудачном DELETE
удалённый элемент восстанавливается на прежнюю позицию.

Регистрация выполняется запросом POST /auth/register, затем клиент выполняет
POST /auth/login и сохраняет полученный токен. Регистрация назначает роль user.
Она не даёт административных прав.

4. ИНСТРУКЦИЯ ЗАПУСКА И ПРОВЕРКИ

В корневом .env должны быть настроены DATABASE_URL и JWT_SECRET длиной не
менее 32 байт. Секреты и пароли не включаются в отчёт и скриншоты.

Терминал №1, корневая папка проекта:

    npm.cmd install
    npm.cmd run dev

Терминал №2, также корневая папка:

    npm.cmd --prefix client install
    npm.cmd --prefix client run dev

Открыть URL клиента, который напечатан Vite (обычно
http://localhost:5173 или http://127.0.0.1:5173).

Для записи плейлистов пользователь должен иметь роль admin. Новая регистрация
по умолчанию создаёт пользователя с ролью user. Назначение роли выполняется
вручную доверенным администратором в PostgreSQL:

    UPDATE users SET role = 'admin' WHERE email = 'your-email@example.com';

Подставить email своей учётной записи. Публичного API для повышения роли нет.
После изменения роли войти в аккаунт заново и проверить роль в интерфейсе.

Проверка операций:

1. Открыть сайт и дождаться загрузки списка.
2. Создать аккаунт либо войти под существующим.
3. Для CRUD войти под аккаунтом admin.
4. Создать плейлист в форме; убедиться, что он появился в списке.
5. Изменить его; убедиться, что обновлённые данные показаны.
6. Удалить тестовый плейлист.
7. Для проверки ошибки остановить сервер, перезагрузить клиент и проверить
   сообщение об ошибке; после запуска сервера нажать «Повторить запрос».
8. Чтобы показать AbortController, инициировать загрузку и размонтировать
   компонент до ответа либо использовать инструменты разработчика браузера
   с замедлением сети; отменённый запрос не должен обновлять размонтированный
   компонент.

6. ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

Примечание: вопросы ниже составлены по темам лабораторной. Если преподаватель
выдал отдельный список из 16 вопросов, перед сдачей заменить формулировки,
сохранив подходящие ответы.

1. Что такое клиент-серверная архитектура?
Клиент отображает интерфейс и отправляет запросы; сервер принимает запросы,
выполняет бизнес-логику и возвращает ответы. В этой работе React — клиент,
Express — сервер, PostgreSQL — хранилище.

2. Что такое REST API?
Это интерфейс взаимодействия ресурсов по HTTP. Ресурс в проекте —
плейлист, доступный по маршруту /playlists.

3. Для чего используется HTTP GET?
GET запрашивает представление ресурса и не должен изменять сохранённые данные.
В работе GET /playlists получает список плейлистов.

4. Для чего используются POST, PUT и DELETE?
POST создаёт ресурс, PUT полностью обновляет ресурс по идентификатору, DELETE
удаляет ресурс. В работе это POST /playlists, PUT /playlists/:id и
DELETE /playlists/:id.

5. Что такое Fetch API и Axios?
Fetch — встроенный API браузера для HTTP-запросов. Axios — библиотека,
предоставляющая удобные методы запросов, преобразование JSON, перехватчики и
интеграцию с AbortController. В проекте запросы выполняются Axios.

6. Что такое Promise?
Promise представляет результат асинхронной операции: ожидание, успешное
завершение или ошибку. В цепочке .then обрабатывается успех, .catch — ошибка.

7. Для чего применяются async и await?
Они позволяют записывать асинхронный код в последовательной форме.
await приостанавливает выполнение текущей async-функции до результата Promise;
ошибки можно обрабатывать блоком try/catch.

8. Зачем в React нужны состояния loading и error?
loading сообщает, что запрос ещё выполняется, и позволяет показать индикатор.
error хранит сведения об отказе и позволяет вывести сообщение и предложить
повторить запрос.

9. Что такое оптимистическое обновление?
Это немедленное изменение интерфейса до ответа сервера. Если запрос успешен,
временное состояние заменяется серверным результатом; если нет — выполняется
откат к прежнему состоянию.

10. Как реализован откат при ошибке создания?
Перед POST плейлист добавляется в состояние с временным ID. При успехе он
заменяется объектом сервера; при ошибке удаляется из состояния и показывается
сообщение.

11. Как реализован откат при ошибке редактирования и удаления?
При редактировании хранится исходный объект, который восстанавливается при
ошибке PUT. При удалении запоминаются объект и его позиция; при ошибке DELETE
объект возвращается в список на прежнее место.

12. Что делает useEffect?
useEffect выполняет побочные эффекты после отрисовки React-компонента:
например, загрузку данных. Функция очистки эффекта отменяет запросы или
освобождает другие ресурсы.

13. Для чего используется AbortController?
Он отменяет Fetch/Axios-запрос через сигнал AbortSignal. Это полезно, если
компонент размонтирован или запрос устарел. В работе отменяется первоначальная
загрузка списка и профиля при очистке эффекта.

14. Как передаётся JWT и зачем нужен Authorization Bearer?
Клиент добавляет заголовок Authorization: Bearer <token>. Сервер проверяет
подпись и срок токена, извлекает пользователя и применяет авторизацию.
Пароль пользователя в токене не передаётся.

15. Где хранится JWT в этой реализации и каковы риски?
В учебном проекте токен хранится в localStorage и добавляется Axios
interceptor. Скрипт на странице, получивший выполнение через XSS, потенциально
может прочитать localStorage; в реальных приложениях рассматривают защиту от
XSS и HttpOnly Secure cookies.

16. Как проверить работу API и безопасность роли?
Проверить GET и CRUD по их HTTP-методам и статусам, повторить запись без токена
и под ролью user, затем выполнить её под admin. Сервер, а не только интерфейс,
должен отклонять запросы без прав. Регистрация не назначает роль admin.


7. ВЫВОДЫ

В ходе лабораторной работы React-клиент был связан с REST API проекта.
Плейлисты загружаются с сервера и сохраняются в PostgreSQL, а интерфейс
обрабатывает загрузку, ошибки, регистрацию и вход. Для создания, редактирования
и удаления применено оптимистическое обновление с откатом при ошибке. JWT
автоматически добавляется к запросам, а сервер проверяет права пользователя.
Дополнительное улучшение — отмена GET-запросов при очистке эффекта.
