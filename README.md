# Lab 2.1 — REST API плейлистов

Курсовой проект: **платформа для совместного прослушивания музыки и создания плейлистов в реальном времени**.

Дополнительные материал
Ресурс API: `/playlists` (не `/items` и не `/contests`).

Данные хранятся **в массиве в памяти**. После перезапуска сервера всё возвращается к трём стартовым плейлистам.

---

## 1. Как запустить

В терминале Cursor, папка `D:\итивп`.

Если `npm` ругается на политику PowerShell, пиши `npm.cmd`:

```powershell
npm.cmd install
npm.cmd run dev
```

Когда всё ок, в терминале будет:

```
Server running on http://localhost:3000
```

Этот терминал **не закрывай**. Сервер работает, пока открыт процесс `nodemon`.

Открой в браузере: [http://localhost:3000/playlists](http://localhost:3000/playlists)

---

## 2. Что видно в браузере

Браузер умеет только **GET**. Ты увидишь JSON, не сайт с кнопками.

| Ссылка | Что должно быть |
|--------|-----------------|
| http://localhost:3000 | краткое описание API |
| http://localhost:3000/playlists | список из 3 плейлистов (`Evening Chill`, `Party Room #12`, `Study Session`) |
| http://localhost:3000/playlists/1 | один плейлист с `id: 1` |

Если страница не открывается — сервер не запущен.

POST / PUT / DELETE в браузере **не сделать**. Для них нужен Postman.

---

## 3. Как проверить всё в Postman (для скриншотов отчёта)

1. Скачай [Postman](https://www.postman.com/downloads/).
2. New → HTTP Request.
3. Сервер должен быть запущен (`npm.cmd run dev`).

### Рисунок 6 — GET список

- Method: **GET**
- URL: `http://localhost:3000/playlists`
- Send

Ожидание: **200 OK**, в теле `count` и массив `data` (у нас сразу 3 записи, не пустой `[]`).

### Рисунок 7 — POST создание

- Method: **POST**
- URL: `http://localhost:3000/playlists`
- вкладка **Body** → **raw** → справа выбрать **JSON**
- вставить:

```json
{
  "title": "Late Night Jazz",
  "description": "Джаз для совместного прослушивания",
  "owner": "dave",
  "isPublic": true,
  "tracks": [
    { "title": "Blue Hour", "artist": "Jazz Collective", "durationSec": 276 }
  ],
  "listenersOnline": 1
}
```

- Send

Ожидание: **201 Created**, в ответе `id: 4` (следующий свободный id).

### Рисунок 8 — GET один элемент

- Method: **GET**
- URL: `http://localhost:3000/playlists/4`
- Send

Ожидание: **200 OK**, тот же объект, что создал POST.

### Рисунок 9 — PUT обновление

- Method: **PUT**
- URL: `http://localhost:3000/playlists/4`
- Body → raw → JSON:

```json
{
  "title": "Late Night Jazz Updated",
  "description": "Обновлённый плейлист комнаты",
  "owner": "dave",
  "isPublic": false,
  "tracks": [
    { "title": "Midnight Sax", "artist": "Jazz Collective", "durationSec": 301 }
  ],
  "listenersOnline": 4
}
```

- Send

Ожидание: **200 OK**, в ответе новые `title`, `description`, `isPublic`.

### Рисунок 10 — DELETE удаление

- Method: **DELETE**
- URL: `http://localhost:3000/playlists/4`
- Send (тело не нужно)

Ожидание: **204 No Content** без тела ответа.

Повторный GET `http://localhost:3000/playlists/4` должен дать **404**.

Дополнительно для отчёта:

- GET `http://localhost:3000/playlists/999` → **404**
- POST без `title` / `owner` → **400**

## 4. Таблица маршрутов (таблица 1 для отчёта)

| Метод | Маршрут | Назначение | Успех | Ошибка |
|--------|---------|------------|-------|--------|
| GET | `/playlists` | список плейлистов | 200 | — |
| GET | `/playlists/:id` | плейлист по id | 200 | 400, 404 |
| POST | `/playlists` | создать | 201 | 400 |
| PUT | `/playlists/:id` | полное обновление | 200 | 400, 404 |
| DELETE | `/playlists/:id` | удалить | 204 | 400, 404 |

## 5. Текст в отчёт (можно копировать)

Предметная область — платформа совместного прослушивания музыки и создания плейлистов в реальном времени. Ресурс API — `playlists`. Данные временно хранятся в массиве в памяти сервера.

В процессе тестирования все эндпоинты были проверены с помощью Postman, а также через браузер. При обращении к серверу по адресу `http://localhost:3000/playlists` методом GET возвращается JSON-объект с полями `count` и `data`. В массиве `data` изначально содержатся три тестовых плейлиста (`Evening Chill`, `Party Room #12`, `Study Session`). Это ожидаемое поведение: сервер запущен, маршрут работает, стартовые данные загружены. На рисунке 6 показан ответ GET со списком плейлистов.

Далее был выполнен POST-запрос по тому же адресу с телом в формате JSON: название «Late Night Jazz», описание «Джаз для совместного прослушивания», владелец `dave`, публичность `true`, массив треков. В ответ сервер присвоил плейлисту идентификатор 4 и вернул созданный объект со статусом 201 Created, что иллюстрирует рисунок 7.

Сразу после этого отправлен GET-запрос на `http://localhost:3000/playlists/4`. В ответе присутствует тот же объект, что подтверждает успешное сохранение и извлечение данных — рисунок 8.

Для проверки полного обновления выполнен PUT-запрос на тот же URL. В теле переданы все обязательные поля с изменёнными значениями: название «Late Night Jazz Updated», новое описание, `isPublic: false`, обновлённый список треков. Сервер вернул обновлённый объект со статусом 200 OK — рисунок 9.

Затем отправлен DELETE-запрос на `http://localhost:3000/playlists/4`. Сервер ответил статусом 204 No Content без тела — рисунок 10. Повторный GET по этому id возвращает 404.

В рамках работы реализованы пять основных маршрутов. Все методы и маршруты показаны в таблице 1.

## 6. Чем этот проект отличается от примера с `/contests`

| В примере про конкурсы | У тебя |
|------------------------|--------|
| URL `/contests` | URL `/playlists` |
| GET сразу пустой `[]` | GET сразу 3 плейлиста |
| DELETE → 204 без тела | DELETE → 204 без тела |
| поля: даты, статус конкурса | поля: `title`, `owner`, `tracks`, `listenersOnline` |

Не копируй из чужого отчёта `[]`, `204` и слово «конкурс».
