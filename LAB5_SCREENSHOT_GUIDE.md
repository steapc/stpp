# Лабораторная работа №5 — инструкция по скриншотам и листингам

В этом файле описано, как самостоятельно получить настоящие снимки экрана для
отчёта по текущему приложению плейлистов. Скриншоты делаются из запущенного
проекта; демонстрационные изображения вместо результатов не используются.

## 1. Перед началом

### Запусти сервер и клиент

В первом терминале, из корневой папки репозитория:

```powershell
npm.cmd run dev
```

Оставь окно работающим. В логе Nodemon должно появиться `Server running on
http://localhost:3000`.

Во втором терминале, также из корневой папки:

```powershell
npm.cmd --prefix client run dev
```

Открой точно тот Vite-адрес, который напечатан в терминале; в обычном запуске
это `http://localhost:5173`. Не подменяй `localhost` на `127.0.0.1`: сервер
разработки может слушать только IPv6 localhost. Если браузер показывает ошибку
API, проверь, что запущен backend. Не запускай второй экземпляр сервера на том
же порту: ошибка `EADDRINUSE` означает, что порт 3000 уже занят.

### Подготовь браузер и снимок

1. Открой сайт в Chrome или Edge.
2. Открой DevTools клавишей `F12`.
3. Перейди на вкладку **Network**. Включи запись (круглая кнопка) и отметь
   **Preserve log**. Не включай **Disable cache** без необходимости: эта
   настройка замедляет также загрузку JavaScript и CSS.
4. Для замедления запросов открой список **No throttling** и выбери **Slow 3G**
   или пользовательский режим с высокой задержкой. Сначала загрузи приложение
   без замедления, затем выбери профиль сети. Для обычных кадров после
   демонстрации верни **No throttling**.
5. Снимай нужную область сочетанием `Win + Shift + S`. Вставляй снимок в отчёт
   рядом с подписью рисунка. Не показывай пароль, заголовок `Authorization`,
   значение JWT, `JWT_SECRET` или `DATABASE_URL`.

Для вставки изображения в Word открой отчёт, поставь курсор вместо
`[ВСТАВИТЬ СКРИНШОТ]` и используй **Вставка → Рисунки**. Под снимком оставь
соответствующую подпись, например «Рисунок 2 — Список плейлистов,
загруженный с сервера».

## 2. Снимки по рисункам

### Рисунок 1 — Индикатор загрузки

1. Сначала открой страницу при **No throttling** и дождись карточек, чтобы
   клиентский JavaScript успел загрузиться.
2. В DevTools → **Network** выбери **Slow 3G** (или медленный профиль) и
   очисти список запросов.
3. Перезагрузи страницу (`Ctrl + R`). До запуска React HTML показывает
   «Загружаем приложение…»; после запуска React начнётся запрос API и появится
   текст «Загружаем плейлисты с сервера…».
4. Для рисунка 1 сделай снимок после появления именно текста про плейлисты.
   Убедись, что `GET /api/playlists` виден в Network как ожидающий запрос.
5. Если загрузка JavaScript замедлена, подожди: HTML-заставка видна раньше,
   а индикатор API появляется только после запуска React.
6. Если API-запрос завершился слишком быстро, создай в throttling профиль
   **Custom** с задержкой (Latency) около `3000 ms`, оставив достаточную
   скорость загрузки и выгрузки, и повтори.

**Что подтверждает:** React-индикатор показывается, пока `isLoading` равен
`true`. HTML-заставка отдельно закрывает пустой экран, пока браузер скачивает и
запускает клиентский JavaScript.

**Код:** [client/src/App.jsx](./client/src/App.jsx), `App` — эффект загрузки
`getPlaylists` и ветка `isLoading` в JSX; [client/src/App.css](./client/src/App.css)
— `.loading-state`, `.loading-spinner`, `@keyframes loading-spin`;
[client/index.html](./client/index.html) — начальная HTML-заставка до запуска
React.

Фрагмент условного отображения:

```jsx
{isLoading ? (
  <p className="empty-state loading-state" role="status">
    <span className="loading-spinner" aria-hidden="true" />
    Загружаем плейлисты с сервера…
  </p>
) : loadError ? (
  // Отображается сообщение об ошибке и кнопка повторного запроса.
) : (
  // Отображается загруженный список.
)}
```

### Рисунок 2 — Загруженные плейлисты

1. Дождись ответа `GET /api/playlists` со статусом `200`.
2. Убедись, что индикатор исчез и на странице видны карточки плейлистов.
3. Сделай снимок, где различимы заголовок раздела, количество плейлистов и
   несколько карточек. В Network можно оставить выделенным запрос
   `GET /api/playlists` со статусом `200`, если он не закрывает интерфейс.

**Что подтверждает:** клиент получает список с API, а API читает данные из
PostgreSQL. Не подписывай скриншот как «из базы», если на нём нет успешного
запроса или иного подтверждения источника данных.

**Код:** [client/src/api.js](./client/src/api.js), `getPlaylists`;
[client/src/App.jsx](./client/src/App.jsx), эффект загрузки и
`visiblePlaylists.map`; серверные маршруты:
[routes/playlistRoutes.js](./routes/playlistRoutes.js) и
[controllers/playlistController.js](./controllers/playlistController.js).

### Рисунок 3 — Создание плейлиста: до и после

Сделай два снимка и помести их рядом под одной подписью.

**Снимок «до отправки»:**

1. Войди в приложении под аккаунтом с ролью `admin`. Новая регистрация
   получает `user`, поэтому сначала администратор должен назначить аккаунту
   роль через PostgreSQL.
2. Заполни форму названием, владельцем и, по желанию, описанием и треками.
3. До нажатия кнопки сделай снимок формы с заполненными данными.

**Снимок «после добавления»:**

1. Если нужно показать оптимистическое обновление, включи Network throttling
   на **Slow 3G**.
2. Нажми **Создать плейлист**. Пока POST ожидает ответ, временная карточка
   появляется в списке. Сделай снимок с карточкой и ожидающим запросом
   `POST /api/playlists`.
3. Дождись ответа сервера. Запрос должен завершиться статусом `201`, а карточка
   остаётся в списке уже с ID и данными, возвращёнными сервером.
4. Сделай отдельный снимок результата, если на предыдущем запрос ещё был
   pending.
5. Верни throttling в **No throttling**.

**Что подтверждает:** POST отправляет данные в сервер, а сервер сохраняет
плейлист в PostgreSQL. Чтобы дополнительно проверить запись, можно обновить
страницу и убедиться, что объект загружается снова через GET.

**Код:** [client/src/App.jsx](./client/src/App.jsx), `submitForm` — создание
`temporaryPlaylist`, вставка во временное состояние, вызов `createPlaylist`,
замена временного объекта ответом сервера и удаление временного объекта при
ошибке; [client/src/api.js](./client/src/api.js), `createPlaylist`;
[routes/playlistRoutes.js](./routes/playlistRoutes.js), POST-маршрут;
[controllers/playlistController.js](./controllers/playlistController.js),
`createPlaylist`.

Фрагмент оптимистического добавления:

```js
setPlaylists((currentPlaylists) => [temporaryPlaylist, ...currentPlaylists])

try {
  const savedPlaylist = await createPlaylist(playlistData)
  setPlaylists((currentPlaylists) =>
    currentPlaylists.map((playlist) =>
      playlist.id === temporaryId ? savedPlaylist : playlist,
    ),
  )
} catch (error) {
  setPlaylists((currentPlaylists) =>
    currentPlaylists.filter((playlist) => playlist.id !== temporaryId),
  )
}
```

### Рисунок 4 — Удаление плейлиста

1. Убедись, что вошёл пользователь `admin`.
2. Выбери тестовый плейлист и нажми **Удалить**.
3. Карточка исчезает сразу, до ответа DELETE. Сними этот момент при замедленной
   сети, если нужно отдельно показать оптимистическое удаление.
4. Дождись ответа `DELETE /api/playlists/:id` со статусом `204 No Content`.
5. Сделай снимок страницы после ответа: карточки больше нет, показано
   сообщение об удалении. Для отчёта используй только тестовый плейлист, который
   можно удалить без потери нужных данных.

**Что подтверждает:** успешное удаление через API; ответ `204` не имеет тела.

**Код:** [client/src/App.jsx](./client/src/App.jsx), `removePlaylist` —
сохранение индекса, немедленное удаление из состояния и восстановление при
ошибке; [client/src/api.js](./client/src/api.js), `deletePlaylist`;
[routes/playlistRoutes.js](./routes/playlistRoutes.js), DELETE-маршрут.

### Рисунок 5 — Ошибка при недоступном сервере

1. Оставь Vite-клиент работающим.
2. Перейди в терминал сервера и нажми `Ctrl + C`, чтобы остановить Express.
   Не закрывай терминал клиента.
3. В браузере перезагрузи страницу.
4. Дождись ошибки загрузки. На снимке должны быть видны текст о невозможности
   загрузить плейлисты, диагностическое сообщение и кнопка
   **Повторить запрос**.
5. Сделай снимок ошибки.
6. Вернись в серверный терминал и снова запусти `npm.cmd run dev`. Дождись
   строки `Server running on http://localhost:3000`.
7. Вернись в браузер и нажми **Повторить запрос**. Список должен загрузиться.

**Важно:** не запускай второй сервер, пока первый ещё слушает порт 3000. Если
получил `EADDRINUSE`, значит старый процесс сервера остался запущенным. Найди
его терминал и останови через `Ctrl + C`; не останавливай процесс PostgreSQL.

**Код:** [client/src/App.jsx](./client/src/App.jsx), `.catch` в эффекте
загрузки, `loadError` и `retryLoading`; [client/src/api.js](./client/src/api.js),
`getApiErrorMessage`.

### Рисунок 6 — Дополнительное улучшение: отмена запроса

В проекте выбрано дополнительное улучшение **AbortController для отмены GET при
очистке эффекта**. Для наглядной проверки в режиме разработки используется
React `StrictMode`: он специально проверяет корректность эффектов, вызывая
цикл setup → cleanup → setup. Поэтому первый GET при первоначальном
монтировании может быть отменён, а следующий завершиться успешно.

1. Открой DevTools → **Network**, включи **Preserve log** и **Disable cache**.
2. Очисти список запросов и перезагрузи страницу.
3. Отфильтруй запросы по `playlists`.
4. Найди отменённый `GET /api/playlists` (Chrome/Edge может показать статус
   `(canceled)` или `(failed)` с причиной `net::ERR_ABORTED`) и следующий
   успешный GET со статусом `200`. Для совмещения адреса и списка расширь
   DevTools или сделай два снимка, если на одном экране всё нечитаемо.
5. Сделай снимок Network и, если возможно, видимой страницы.

Если отменённый запрос не успел появиться из-за очень быстрой сети, выбери
более медленный throttling, очисти Network и снова перезагрузи. Не останавливай
API во время этой проверки: этот рисунок должен показывать именно отмену
запроса, а не сетевую ошибку.

**Код:** [client/src/main.jsx](./client/src/main.jsx), `<StrictMode>`;
[client/src/App.jsx](./client/src/App.jsx), эффекты `getPlaylists` и
`getProfile`, создание `AbortController`, передача `signal` и вызов
`controller.abort()` в cleanup; [client/src/api.js](./client/src/api.js),
передача `signal` в Axios.

Ключевой фрагмент:

```js
const controller = new AbortController()

getPlaylists({ signal: controller.signal })
  .then((data) => setPlaylists(data))
  .catch((error) => {
    if (error.name !== 'CanceledError') {
      setLoadError(getApiErrorMessage(error))
    }
  })

return () => controller.abort()
```

В компоненте дополнительно используется флаг `isActive`, чтобы результат
старого эффекта не менял состояние после очистки. Отмена запроса не должна
показываться пользователю как обычная ошибка загрузки.

## 4. Вставка скриншотов в отчёт

В [LAB5_REPORT.txt](./LAB5_REPORT.txt) найди раздел **«5. СКРИНШОТЫ»**.
Для каждого рисунка:

1. Сделай настоящий снимок своего браузера и/или DevTools, выполняя шаги выше.
2. Вставь снимок в документ Word под подходящей подписью. Файл TXT сам по себе
   не предназначен для встраивания изображений.
3. Удали соответствующую пометку `[ВСТАВИТЬ СКРИНШОТ]` из копии отчёта.
4. Для рисунка 3 вставь оба состояния — заполненная форма до отправки и
   появившаяся карточка после добавления.
5. Не заявляй о статусе `201`, `204` или `(canceled)`, если не проверил его
   в Network/ответе сервера.

Перед сдачей проверь, что на снимках нет пароля, JWT, заголовка Authorization,
секрета `JWT_SECRET`, строки подключения к БД и личных данных, которые не
требуются для демонстрации.
